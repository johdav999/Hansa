# TR-08 — Merchant-office specializations and advanced commerce

Status date: 2026-09-21.

## Implemented contract

Every authored city trade policy exposes one `MerchantOfficePrimary` exclusive group with three choices. A branch requires an active Merchant Office and active station. Selection and respec use the single authoritative `ApplyPresenceSpecialization` command with the reviewed specialization revision and station inventory as the funding inventory. Validation and payment happen against a candidate state; money and goods commit only when every prerequisite, identity, capacity, resource, and exclusivity check succeeds.

| Branch | Investment | Concrete runtime effect |
| --- | --- | --- |
| Warehouse | 90,000 pfennig, 8,000 planks, 1,000 tools | Adds 75,000 milli-units to the same station inventory's authoritative capacity. |
| Market | 75,000 pfennig, 6,000 planks, 2,000 tools | Adds four standing-order slots and grants reviewed price-limited orders. Acquire limits execute at or below the ceiling; release limits execute at or above the floor. |
| Harbor | 110,000 pfennig, 10,000 planks, 3,000 tools | Adds 50,000 milli-units to the per-operation station transfer/handling cap used by physical route transfers. |

All three grant separate typed capabilities consumed by runtime systems. Bonuses are bounded and derived from the single selected stable branch ID, so they cannot stack. Respec is explicit: 25% of the replaced branch's money investment is returned, invested goods are not returned, and the replacement's full money/goods cost is revalidated and consumed atomically. Closing the station clears its active branch and advances the specialization revision. Unknown, stale, unaffordable, duplicate, wrong-stage, wrong-inventory, and conflicting selection requests reject without mutation.

Price-limited orders sample the current friction-adjusted settlement price at command validation. The client supplies the market update tick and reviewed unit price; either changing rejects as `StationOrderStaleReview`. A limit of zero is the canonical disabled state. Runtime execution uses the same settlement price and inclusive comparison, records `PriceLimit` as the causal blocker, moves no goods, and spends no money while blocked.

## UI and authoring

The native Trade Map comparison surface exposes Warehouse, Market, and Harbor as ordinary focusable controls with stable semantic IDs. It presents exact money/material costs, concrete capacity/order/handling deltas, exclusivity, selected state, availability/blocker, and money-only respec refund before a separate confirmation action. Dynamic text and values are native Slate; no generated full-screen raster ships.

Component inventory: Trade Map shell; specialization navigation/selection; three comparison rows/cards; exact cost and delta lists; confirm/respec control; selection, opportunity-cost, warning, error and success feedback; capability icons; restrained brass dividers. Covered states are default, hover/native button state, selected, disabled/unavailable, keyboard/controller focus, loading/refresh, warning, stale/error, and confirmation feedback.

The reflected city-policy branch array carries stable IDs, exclusive group, prerequisite stage, typed capability references, investment goods, bounded deltas, and respec policy. Compiler validation rejects duplicates, missing references, invalid costs/deltas, malformed exclusivity, and unknown capabilities. Definition hashing, deterministic schema export, generic Authoring Studio reflection, reverse relationship/impact analysis, and save migration cover the branch graph.
