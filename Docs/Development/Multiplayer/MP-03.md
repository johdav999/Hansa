# MP-03 — real identity binding and secure admission

Executed 2026-09-19 against the working checkout. Unrelated source, content, generated-build, and documentation changes were preserved.

## Result

MP-03's provider-neutral admission gate passes. A server-owned admission service now validates a canonical identity returned by an authentication adapter, resolves that identity through a server-side participant/house binding, and returns a secret-free admission capability. `FHansaMultiplayerAuthority` no longer accepts a raw principal/house pair. Normal network `PostLogin` fails closed until the session layer supplies validated admission; first-available assignment remains only in the explicit `-HansaAuthorityFixture` path and local standalone composition.

The selected live EOS provider is still intentionally deferred to MP-10. MP-03 uses a deterministic authentication-adapter mock and does not add provider SDKs, credentials, or account identifiers to gameplay state.

## Implementation

- Added `FHansaAdmissionService` in the runtime-only `HansaSimulation` module.
- Kept provider account identifiers and credential records outside `FHansaSessionState`, deterministic saves, projections, and public session metadata.
- Added exact protocol, definition/content-manifest, and scenario compatibility checks before a capability can reach the authority layer.
- Added server-side identity-to-participant/house bindings, reservation policy, friend/invite/closed policy checks, bans, duplicate-login rejection, and bounded two-to-eight-session capacity enforcement.
- Added real-time admission deadlines independent of simulation time and a bounded request-nonce replay window.
- Added explicit LAN/offline trust: a LAN client must present a server-issued opaque credential. A display name is never an authentication input.
- Added expiring, single-use, rotating reconnect credentials bound to mode, canonical online identity where applicable, participant, and house. Only a digest is retained by the server; plaintext is returned once and never logged.
- Added stable `HSA-MP03-*` cause/remedy diagnostics that omit proof material, provider identities, and credentials.
- Replaced `RegisterClient(principal, house, ...)` with `RegisterAdmittedClient(FHansaAdmissionGrant, ...)`; a rejected request receives no valid grant and cannot request a projection.
- Preserved the existing explicit authority process fixture while closing the normal network `PostLogin` first-available path.

No gameplay definition changed, so no definition schema, editor metadata, migration, impact-analysis, generation schema, or content catalog update was applicable. No GUI was designed or materially changed, so the GUI/ImageGen contract was not applicable.
