The authored Lübeck scenario now has eight stable house slots, eight independent economies, a starting route and vehicle for every house, and a finite non-overlapping buildable opportunity for every house. The authority admits distinct participants to those houses, rejects a ninth or competing claim, and transitions a house atomically between AI, human, and policy-controlled dormant ownership without creating gameplay assets.

## Implementation

- Added a runtime-only eight-house control roster with stable house and participant IDs, explicit human/AI/dormant states, per-house takeover and AI-resume policies, and monotonically increasing control epochs.
- Made a human claim reject duplicate participants and already-human-controlled houses before mutation. An accepted claim changes the roster to human control in one transition, so the AI gate observes the new state before any client registration completes.
- Made release resume AI only when the authored session policy permits it; otherwise the house becomes dormant.
- Replaced the single rival-AI owner with one deterministic controller per AI-capable house. Each simulation tick selects at most one eligible AI house, preventing competing AI and human command streams or duplicate same-tick command ordering.
- Expanded scenario initialization from two to eight houses. Houses 1–8 receive independent money/research state; every house receives a stable starting route, vehicle, and inventory.
- Partitioned the current Lübeck land cells deterministically among all eight houses, preserved existing placed-building ownership, duplicated the authored construction entitlements, selected unique unoccupied start anchors, and recorded the exact finite buildable-cell count for each house.
- Generalized the runtime host to expose the stable house roster and starting opportunities and to claim/release a house through the control policy. Save ownership metadata now enumerates all eight houses, and deterministic runtime save/restore continuation remains valid.
- Generalized authority registration to bind the admitted participant to the requested house through the host control roster. Unregistering immediately revokes projection access and releases the house according to policy.
- Generalized the explicit fixture/standalone game-mode composition to choose the first unclaimed authored house up to the eight-house scenario bound. Normal unauthenticated network joins remain rejected.
- Kept the legacy primary/rival accessors only as standalone/UI compatibility aliases for houses 1 and 2. Server command routing and owner projections use the admitted client’s bound house. The full current-action command inventory remains MP-05 scope.
- Audited scoreboard references: this checkout has no implemented scoreboard subsystem to migrate. Public house/victory data continues through the authority projection rather than a separate two-house scoreboard.
- Added deterministic coverage for eight-human/zero-AI, four-human/four-AI, AI-to-human takeover, policy-controlled AI resumption, simultaneous competing claims, ninth-client rejection, immediate revocation, and a replacement-human swap with unchanged house/route asset counts.
