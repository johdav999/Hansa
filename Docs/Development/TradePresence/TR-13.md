# TR-13 — Suspension, revocation, closure, recovery, and compatibility hardening

Status: implemented and focused evidence verified 2026-09-21. Save format **21** and deterministic fingerprint **33** add an authoritative, orthogonal trade-station operating condition. Gameplay command schema remains **14**, multiplayer client intent remains **7**, and simulation/pipeline remain **1/1** because recovery reuses the existing fund, close, station-order, and route commands.

## Recovery contract

`EHansaTradeStationOperationalState` is persisted independently of the construction lifecycle. This avoids interpreting every suspension as a closure and lets the game preserve the station aggregate while explaining the exact interruption.

| State | Continues | Pauses or blocks | Cost | Recovery |
| --- | --- | --- | --- | --- |
| Active | Orders, inbound/outbound routes, construction rights, existing buildings | Nothing | Exact authored upkeep each tick | None |
| Underfunded | Outbound cargo recovery and inspection | Orders, inbound transfers, new leased construction, dependent routes at a safe stop | One exact missed upkeep charge is retained as arrears; new upkeep pauses | Existing Fund station action pays arrears; routes are resumed explicitly |
| Storage blocked | Outbound station loads and release orders | Inbound station unloads and acquisition orders | Upkeep continues | Load a berthed owned Cog or release stock |
| Orders suspended | Routes, storage, leased buildings | All live factor orders are paused | Upkeep continues | Resume or replace an order |
| Rights suspended | Inspection, owned outbound cargo recovery, existing building identities | Inbound transfers, orders, new leased construction, dependent routes | New station upkeep pauses | Restore the authored presence rights, then resume routes |
| Voluntarily closed | Inspection, existing buildings, reservations, and owned outbound cargo recovery | Orders, inbound transfers, new leased construction; routes at the station pause | New station upkeep pauses | Empty cargo, release reservations, remove leased buildings, then close again to release the plot |
| Revoked | Inspection and owned outbound cargo recovery | Normal station commerce and construction rights | New station upkeep pauses | Recover property; the revoked right itself requires a new authored grant |

Existing leased buildings, production records, worker assignment inputs, cargo, reservations, orders, route plans, stable IDs, and presence history are never erased by an interruption. Current production/building systems remain authoritative for already placed buildings; an inactive lease blocks new placement. If station access prevents an input flow, the normal production blocker exposes that consequence.

## Closure and route behavior

The first close command is always non-destructive. It marks the station voluntarily closed, pauses live orders, disables the lease for new construction, and safely pauses dependent routes already at a stop. The route receives a deterministic missed transfer receipt. A route already traveling completes its current leg and records the normal missed station action on arrival.

Cargo and reservations remain in the station inventory. `StationLoad` is the only station transfer authorized while interrupted, so an owned berthed Cog can recover stock without reopening inbound commerce. When storage and reservations are zero and the leased plot has no occupying buildings, a close command finalizes the closure, releases plot occupancy, and returns the presence to its authored opening stage. An already empty station finalizes on the first close, preserving the prior ordinary-game flow.

All transfer work still uses the candidate inventory ledger and only commits after validation. Rejected arrears payments, duplicate identities, invalid commands, and incompatible save loads leave the caller's authoritative state unchanged.

## Player-facing recovery surface

The Trade Map and station inspector use native controls and the existing approved Trade Presence visual family. No new raster asset was needed. The UI presents the operational state, physical used/reserved capacity, upkeep and arrears, what is preserved, what continues to cost money, the blocker, and the next recovery step. Closed stations remain selectable until recovery/finalization is complete.

TR-13 fixed pre-existing admission gaps for `10/23`, `11/24`, and `19/31`. Migration `Hansa.Save.20To21.AddRecoverableTradeStationInterruptions` maps old active, suspended, and closed lifecycles to explicit operating states without inventing cargo, debt, or rights.

The test-only historical encoder writes the actual conditional field layout for formats 1 through 20. `Hansa.Integration.Save.EveryIntermediateVersionRecovery` performs an integrity-checked metadata dry run, applies each migration chain, resaves current, repeats the load, verifies that no migration reapplies, and compares the authoritative hash. Checked-in v1 and v2 archives and the prior format-14 station-order fixture remain separate non-generated evidence.

Load failures now distinguish:

- corrupt/truncated/checksum-invalid archives, with backup guidance;
- a removed city policy;
- a missing station-site definition;
- changed leased-plot bounds, while explicitly stating that saved cargo/buildings were not deleted;
- an active station whose migrated presence lacks the TradeStation capability;
- an unknown save/fingerprint pair requiring an explicit migration.
