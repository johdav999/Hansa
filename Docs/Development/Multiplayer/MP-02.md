# MP-02 — versioned session, participant, and permissions model

Executed 2026-09-19 against the working checkout. Unrelated source, content, generated-build, and documentation changes were preserved.

## Result

MP-02's model gate passes. Runtime code now has separate stable campaign, session, participant, house, and team identities; bounded two-through-eight scenario slots; human, AI, open, closed, and reserved states; participant lifecycle and host/admin roles; a compatibility tuple; and explicit per-house access grants. Connection handles, display names, and provider account identifiers are deliberately absent from the gameplay model.

The policy is server-evaluable and deny-by-default. Public facts are readable without a private grant, team facts require current team membership, house-private facts require ownership or `ReadPrivate`, and economic/asset/agreement mutations require ownership or their specific grant. Team membership alone does not grant destructive access. MP-06 and MP-16 still own projection filtering, live revocation, and full cooperative-mode integration.

## Implementation

- Added stable entity-ID domains `Campaign`, `Session`, `Participant`, and `Team` alongside the existing `House` identity.
- Added the provider-neutral `FHansaSessionModel` in `HansaSimulation`, including:
  - protocol/content/scenario compatibility;
  - slot, participant, role, lifecycle, team, and bounded grant records;
  - deterministic validation with stable cause/remedy diagnostics;
  - public/team/private read policy and scoped action policy;
  - bounded deterministic binary serialization;
  - format-1 to format-2 migration separating session identity and adding team/grant policy.
- Extended `UHansaScenarioDefinition` to schema 2 with reflected multiplayer slot rules, full authoring metadata, generic schema export, deterministic hash coverage, validation, compiler output, seed/copy support, and a schema-1 load migration.
- Authored compatible defaults for the current two-house scenario: `HouseSlot.Primary` begins human and `HouseSlot.Rival` begins AI; both may use all five slot states. MP-04 owns expansion to eight playable authored houses and starting opportunities.
- Advanced the reviewed economic catalog from v30 (`3472D1CD822731FA`) to v31 (`B8CA5DD8041EF027`). The only definition fingerprint delta is `Scenario.LubeckGrainShortageV1`, from `53519ED3DCE8D652` to `7940AD5EFF9AADEF`. Catalog v30 remains preserved, and the compatible definition migration is named `Hansa.Content.30To31.AddScenarioMultiplayerSlotRules`.
- Added runtime and editor fixture coverage. No online-service SDK, editor module, provider ID, credential, or connection identity enters `HansaSimulation`.
