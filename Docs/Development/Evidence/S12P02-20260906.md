# S12-P02 implementation verification — 2026-09-06

The working tree already contained the worker bridge, native job panel, approval controls, provenance, mock tests and visual references when this verification began. This increment preserves that implementation and unrelated work, and completes the responsiveness and approval hardening described below.

## Changes

- Background controller snapshots handle capability/job refresh, input hashing, estimate, submit, cancel, retry and JSON result reads. Slate and UObject operations stay on the editor thread.
- Active queues refresh after each completed operation, with one second between requests. Unchanged selection retains proposal review.
- Thread-safe transport ownership allows a pending request to finish after the tab closes without retaining the widget.
- Overlapped named-pipe I/O has a shared three-second response deadline and cancels pending operations before releasing buffers. Connection has a separate three-second deadline.
- Cost estimates reject invalid amounts, currency mismatches and malformed request hashes. Submission consumes the estimate before dispatch, including a lost-response failure.
- Retry confirmation identifies the selected job and its stored hard budget. Switching jobs or replacing input files clears consent. A new-request estimate cannot authorize another job's retry.
- Regression tests verify estimate failures, upload changes, duplicate-click rejection, native pipe timeout, editor-thread completion and tab closure.
